# ТЗ: Dokkomplekt Universal — план развития (условно v18)

Дата: 15.07.2026. Основание: аудит исходников v17.5.1, анализ рынка (конструкторы документов, МИС, КЭДО, document automation), анализ нормативки (ЕГИСЗ/СЭМД, приказ Минтруда 578н, 63-ФЗ, 152-ФЗ).

---

## 1. Назначение документа

Зафиксировать полный перечень доработок, которые выгодно внести на текущем этапе разработки, с приоритетами, декомпозицией по крейтам и разбивкой по целевым профессиям. Документ — рабочее ТЗ для планирования релизов, не маркетинговый материал.

## 2. Продукт и позиционирование

**Что есть:** локальный офлайн-конструктор DOCX-комплектов (Tauri 2 + Rust + SQLite) с детерминированным извлечением данных из исходников, строгим fail-closed рендером и фоновым watcher'ом.

**Ключевые отличия от рынка** (беречь при любых доработках):
- полная офлайн-работа — данные не покидают машину (аргумент №1 для медицины, юристов под NDA, закрытых контуров);
- работа с *собственными* шаблонами пользователя, а не с продаваемой базой шаблонов;
- комплект документов одной кнопкой + zero-touch папка;
- отсутствие абонентской зависимости от облака.

**Целевой ценовой коридор** (по рынку): 900–3500 ₽/мес за рабочее место. Прямых аналогов в нише «офлайн + свои шаблоны + автоизвлечение» нет; конкуренция — облачные конструкторы (FreshDoc, Doczilla, Комбинатор), встроенные генераторы CRM (Битрикс24, МойСклад), МИС (в медицине), западные Gavel/HotDocs (недоступны/дороги в РФ).

## 3. Приоритеты

| Приоритет | Содержание | Критерий |
|---|---|---|
| **P0** | Ядро шаблонного движка + семантическое ядро + обязательные исправления из аудита | Без этого нельзя выходить ни в одну платную вертикаль |
| **P1** | Доменные пакеты Tier-1 (юристы, бухгалтерия-обвязка, HR + КЭДО-экспорт) | Самый дешёвый вход, самый широкий спрос |
| **P2** | Доменные пакеты Tier-2/3, опциональные онлайн-интеграции, электронная подпись | Расширение ниш |
| **P3** | ЕГИСЗ/СЭМД (медицина как продукт для клиник) | Отдельный проект 4–6 мес., начинать только при подтверждённом спросе |

## 4. P0 — Ядро шаблонного движка

Текущий движок умеет только плоскую подстановку `{{field.id}}`. Для платных вертикалей этого недостаточно. Все функции ниже — универсальные и окупаются во всех доменах сразу.

### 4.1 Условные блоки
- Синтаксис: `{{#if org.type == "ИП"}} ... {{else}} ... {{/if}}`, `{{#unless ...}}`.
- Условия: равенство, наличие/пустота поля, сравнение чисел/дат, логические И/ИЛИ.
- Работают в теле, колонтитулах, сносках (через существующий механизм сшивания разорванных плейсхолдеров).
- Строгий режим: незакрытый блок = ошибка рендера, а не «тихое» поведение.

### 4.2 Повторяющиеся секции и строки таблиц
- `{{#each items}} {{item.name}} — {{item.price}} {{/each}}` для абзацев и **строк таблиц DOCX** (клонирование `<w:tr>`).
- Источник коллекций: semantic case получает типизированные списки (`items[]`, `works[]`, `parties[]`).
- Автоитоги по коллекции: `{{sum items.price}}`, `{{count items}}`.

### 4.3 Вычисления
- Формулы в плейсхолдерах: `{{= amount.total * 0.20}}`, `{{= contract.date + 10 рабочих_дней}}`.
- Денежная арифметика на целых копейках (без float), НДС (20/10/0, «в т.ч.» и «сверху»), проценты, округления.
- Датовая арифметика: календарные/рабочие дни; офлайн-ресурс производственного календаря РФ с ежегодным обновлением (по образцу ICD-10 TSV).

### 4.4 Русская морфология (критично для юристов и HR)
- Склонение ФИО по падежам («в лице директора Иванова Ивана Ивановича, действующего…»), с учётом пола и несклоняемых фамилий.
- Склонение должностей и наименований («генерального директора», «доверенному лицу»).
- Числа, суммы и даты прописью: «Сто сорок шесть тысяч пятьсот рублей 00 копеек».
- Синтаксис-модификаторы: `{{subject.name | genitive}}`, `{{amount.total | words}}`, `{{document.date | words}}`.
- Реализация: отдельный крейт `dokkomplekt-morph` (словарь + правила, без внешних зависимостей; допустимо портировать открытые алгоритмы padeg/petrovich).

### 4.5 Автонумерация и счётчики
- Счётчики документов в SQLite (по типу/году/префиксу): `{{counter contract.number format="Д-{YYYY}/{NNN}"}}`.
- Автонумерация пунктов и подпунктов договора при вставке/удалении условных блоков.

### 4.6 Форматирование значений
- Маски: телефон +7 (XXX) XXX-XX-XX, ИНН/КПП/СНИЛС с разделителями, денежный формат с пробелами.
- Единый формат дат на документ (настраивается в шаблоне).

### 4.7 DOCX-возможности
- Сохранение стилей run'а при подстановке многострочных значений (перенос абзацев).
- Вставка изображений в плейсхолдер: `{{image org.stamp}}` — печать, факсимиле, логотип (PNG/JPEG, с ограничением размеров).

### 4.8 Библиотека блоков (clause library)
- Переиспользуемые фрагменты (реквизитные блоки, типовые оговорки) в SQLite, вставка через `{{block requisites_ooo}}`.
- Блоки могут содержать плейсхолдеры и условия.

### 4.9 Пакетная генерация (mail-merge)
- Вход: CSV/XLSX со строками данных → N комплектов документов (строка = комплект).
- Использует существующий staging и атомарную публикацию; лимиты по тарифу (§10).

## 5. P0 — Семантическое ядро

### 5.1 Расширение реестра полей
Добавить в field_registry (все — с типами и подсказками для LLM-промпта):

- **subject.\*** (физлицо): snils, gender, birth_place, passport_series, passport_number, passport_issued_by, passport_issued_date, passport_code, address_registration, address_actual, phone, email, inn_person.
- **org.\***: ogrn, kpp, okpo, okved, legal_address, actual_address, bank_name, bank_bik, bank_account, bank_corr_account, director_name, director_position, director_basis («на основании Устава/доверенности №…»).
- **employee.\***: tab_number, position, department, hire_date, salary, contract_number.
- **contract.\***: number, date, subject, start_date, end_date, amount, currency, penalty_percent.
- **realty.\***: cadastral_number, address, area, floor, rooms.
- **vehicle.\***: vin, gos_number, brand_model, year, pts_number.
- **doctor.\*** (для медицины и СЭМД-перспективы): snils, position_code, department.

### 5.2 Валидаторы с контрольными суммами
По образцу существующего валидатора ИНН:
- СНИЛС (контрольное число), ОГРН/ОГРНИП (mod 11/13), пара БИК+расчётный счёт (контрольный ключ), корсчёт+БИК, кадастровый номер (формат XX:XX:XXXXXXX:XXX), VIN (формат/чек-цифра), КПП (формат), паспорт РФ (формат).
- Все валидаторы доступны и парсеру, и фильтру предложений внешней LLM (принцип «модель предлагает — валидатор решает» сохраняется).

### 5.3 Офлайн-справочники (крейт `dokkomplekt-refdata`)
По образцу icd10_catalog (OnceLock, ресурс в бинарнике, обновление с релизами):
- банки РФ по БИК (название, корсчёт) — автозаполнение реквизитов офлайн;
- ОКВЭД (коды + названия);
- производственный календарь РФ (текущий + следующий год);
- регионы/типы адресных объектов (лайт, для нормализации адресов);
- базовый список должностей для автодополнения.

### 5.4 Доработки парсера
- **Поддержка ISO-дат** `YYYY-MM-DD` в parse_flexible_date (сейчас возвращает None — дефект).
- Метки-экстракторы для всех новых полей: «ОГРН», «р/с», «к/с», «БИК», «в лице», «действующего на основании», «кадастровый номер», «табельный номер» и т.д.
- Извлечение табличных данных: строки «наименование/кол-во/цена/сумма» → коллекция items[].

## 6. P1–P2 — Доменные пакеты по профессиям

Формат пакета: доменный профиль (метки парсера + словарь) + 8–15 стартовых шаблонов с плейсхолдерами + специфичные поля/валидаторы + пресет папки вывода. Пакеты — контент поверх ядра, кода почти не требуют.

### Tier 1 (P1) — запускать первыми

**6.1 Юристы, адвокаты, юрдепартаменты**
- Документы: договоры (услуги, поставка, аренда, подряд, NDA, займ), доп.соглашения, доверенности, претензии, исковые заявления, ходатайства, протоколы разногласий, юрзаключения, адвокатские запросы.
- Специфика: условные блоки (ИП/ООО/физлицо), морфология («в лице…»), автонумерация пунктов, clause library, реквизитные блоки сторон, расчёт неустойки (ставка × дни).
- Госформатов нет; суды принимают обычные PDF/DOCX через «Мой Арбитр»/ГАС «Правосудие».
- Ценовой ориентир ниши: 1700–3500 ₽/мес.

**6.2 Бухгалтерия / «обвязка сделки» (малый бизнес, ИП, самозанятые)**
- Документы: договор + счёт на оплату + спецификация + акт выполненных работ/услуг + накладная (неформализованная) + доверенность на получение ТМЦ + упрощённый акт сверки.
- Специфика: items[] с итогами и НДС, суммы прописью, автозаполнение банка по БИК, счётчики номеров, QR-код для оплаты (ГОСТ Р 56042, офлайн-генерация — опционально).
- **Вне объёма:** формализованные счета-фактуры/УПД в XML ФНС — территория операторов ЭДО и 1С, не конкурировать.

**6.3 HR / кадры**
- Документы: трудовой договор + доп.соглашения, приказы (приём, перевод, отпуск, увольнение, премирование), заявления, уведомления, согласия на обработку ПДн, ЛНА (положения, инструкции), справки с места работы, характеристики.
- Специфика: employee.\*, морфология, датовая арифметика (отпуска, сроки уведомлений), пакетная генерация (приказ на N сотрудников из CSV).
- **КЭДО-экспорт (приказ Минтруда 578н):** режим «пакет КЭДО» = основная часть PDF/A-1A + XML-описание документа + место под открепленную подпись .sgn, которую ставит внешняя система. Подписание и доставка остаются за оператором КЭДО — Доккомплект встраивается в цепочку до него. Требует PDF-экспорта (§7.3).

### Tier 2 (P2)

**6.4 Медицина (частная практика, отдельные врачи) — довести без ЕГИСЗ**
- Документы: протокол осмотра/консультации, выписной и этапный эпикризы, дневники (план уже есть), направления, справки, информированные добровольные согласия (ИДС) по видам вмешательств, договор на платные медуслуги + акт.
- Специфика: ICD-10 (есть), календарь дневников (есть), ИДС как clause library, поля doctor.\*.
- Позиционирование до P3: «генератор, готовый к СЭМД» — валидный состав полей, подписание/отправка через МИС клиники.

**6.5 Недвижимость / риэлторы**
- Документы: ДКП квартиры/дома/участка, аренда/наём, акт приёма-передачи, расписка о получении денег, агентский договор, соглашение о задатке/авансе, опись имущества.
- Специфика: realty.\* (кадастровый номер с валидатором), суммы прописью, паспортные блоки сторон, условные блоки (ипотека/наличные, с мебелью/без).

**6.6 Строительство / подряд / ремонт**
- Документы: договор подряда, смета-приложение (items[]), акты сдачи-приёмки этапов, акты скрытых работ, гарантийные письма, графики работ, дефектные ведомости.
- Специфика: items[] с итогами, датовая арифметика этапов, счётчики актов. КС-2/КС-3 — только как печатная форма DOCX (полноценный сметный формат вне объёма).

**6.7 Образование (школы, ДПО, репетиторы, автошколы)**
- Документы: договор на обучение, приказы (зачисление/отчисление), справки об обучении, характеристики, ведомости, сертификаты/дипломы ДПО с автонумерацией, расписания-приложения.
- Специфика: пакетная генерация по списку учеников; профиль Education в коде уже определяется — наполнить.

**6.8 ИП / самозанятые / фриланс (сквозной сегмент)**
- Документы: договор-оферта, счёт, акт, бриф-приложение, NDA-лайт.
- Минимальный стартовый пресет из 5 шаблонов; главный канал самостоятельной покупки Trial→Start.

### Tier 3 (P2, контент-паки по мере спроса, нового кода не требуют)

- **6.9 Охрана труда:** приказы о назначении ответственных, программы инструктажей, журналы (печатные формы), перечни СИЗ, положения СУОТ; пакетная генерация по списку сотрудников.
- **6.10 ЖКХ / ТСЖ / УК:** уведомления собственникам (mail-merge по реестру — ключевая фича ниши), протоколы общих собраний, бюллетени, акты осмотра, претензии должникам.
- **6.11 Логистика / транспорт:** договор перевозки/экспедиции, доверенность на водителя, акты приёма груза, претензии; vehicle.\* с VIN-валидатором. ЭТрН в форматах ФНС — вне объёма.
- **6.12 Страхование (агенты/брокеры):** заявления на выплату, описи документов, уведомления о событии, агентские договоры.
- **6.13 Психологи и частная немедицинская практика:** договор услуг, ИДС, заключения по диагностике, справки о посещении.
- **6.14 Ветеринария:** клон мед-профиля без ЕГИСЗ-рисков; поля animal.* (кличка, вид, порода, чип), протоколы приёма, выписки, договор с владельцем.
- **6.15 Госсектор, МСУ, НКО, секретариаты:** письма и ОРД по ГОСТ Р 7.0.97-2016 (бланк с реквизитами, исх./вх. номера), приказы, протоколы, служебные записки; автонумерация исходящих. Для продаж — реестр российского ПО (§9.4).
- **6.16 Автосервис / бытовые услуги:** заказ-наряд, акт приёмки авто/оборудования, квитанции; vehicle.\*.
- **6.17 Туризм:** договор о реализации турпродукта (существенные условия как clause-блоки), памятки, заявки на бронирование.
- **6.18 Наука / гранты / вузы:** сопроводительные письма, отчётные формы, договоры ГПХ, акты.

**Сводно:** Tier 1 закрывает ~70% адресуемого спроса; каждый пакет Tier 2–3 при готовом ядре P0 — оценочно 1–2 недели работы контент-редактора.

## 7. P2 — Интеграции (опциональные, по умолчанию выключены)

Принцип: ядро офлайн; каждая интеграция — отдельный инжектируемый транспорт по образцу существующего `SemanticModel`.

- **7.1 ЕГРЮЛ/ЕГРИП по ИНН** (DaData или API ФНС): автозаполнение org.\* одним полем; кэш в SQLite; явная индикация «данные получены из сети».
- **7.2 Электронная подпись:** адаптер КриптоПро CSP — открепленная CAdES-BES (.sig/.sgn), интерактивная подпись сертификатом пользователя; плюс «ручной» workflow под Госключ (выгрузка файла → подпись на смартфоне → загрузка .sig в комплект). Ed25519-подсистема проекта остаётся только для лицензирования продукта.
- **7.3 PDF-экспорт:** конвертация итогового DOCX в PDF и PDF/A-1A (для КЭДО-пакета §6.3 и печатных форм). Выбрать реализацию на проектировании; PDF/A — обязательное требование.
- **7.4 Локальная LLM как SemanticModel:** готовый транспорт к Ollama/llama.cpp (localhost) — «умное извлечение без интернета»; интерфейс уже есть, технически дёшево, маркетингово сильно.
- **7.5 Экспорт/импорт пакетов шаблонов:** файл-пакет (docx + манифест полей + условия) для обмена между пользователями и будущего каталога.

## 8. P3 — Медицина/ЕГИСЗ (отдельный проект, только при подтверждённом спросе)

- Крейт `dokkomplekt-cda`: генерация СЭМД XML HL7 CDA R2 (уровень 3) по профилям; старт — Протокол консультации, Выписной эпикриз, Справка.
- Крейт `dokkomplekt-nsi`: кэш федеральных справочников НСИ с OID.
- Крейт `dokkomplekt-egisz-client`: транспорт через оператора ИИС (N3.Health, FHIR), очередь отправки со статусами и повторами.
- Двойное подписание УКЭП (врач интерактивно + организация автоматически) через §7.2.
- Неудаляемый локальный архив подписанных СЭМД (РЭМД хранит только подпись и ссылку на хранилище МИС).
- Испытания на тестовом контуре оператора; партнёрский договор с оператором ИИС.
- Оценка: 4–6 месяцев команды. Для отдельных врачей до этого достаточно §6.4.

## 9. Нефункциональные требования и техдолг

### 9.1 Обязательные исправления из аудита v17.5.1 (P0, до новых фич)
1. Устранить скрытую панику в `source_parser::find_labeled_value` (байтовые смещения при lowercase) — переиспользовать корректный `semantic_engine::find_label_end`.
2. Подключить лицензирование к генерации: `evaluate_access` перед рендером, вотермарки Trial/Demo в DOCX, учёт UsageLedger, месячные/разовые лимиты.
3. Платёжный вебхук: fail-closed при отсутствии настроенного секрета (сейчас fail-open).
