# Канонический конвейер Dokkomplekt 18.2.2

Этот документ фиксирует единственный поддерживаемый маршрут обработки и границы модулей. Названия близки по смыслу, но слои не должны дублировать ответственность.

## 1. Intake и нормализация — Tauri shell

`src-tauri/src/universal_intake.rs` отвечает только за ввод и преобразование форматов:

- DOCX/DOCM, PDF, изображения, XLSX/XLS/ODS, ODT/RTF, EML/MSG, архивы и HTTPS-источники;
- безопасный запуск проверенных sidecar;
- OCR и нормализацию в текст;
- ограничения размера, глубины и времени;
- отсутствие отраслевых выводов.

Он не решает, какое поле найдено, и не строит workflow.

## 2. Детерминированное понимание — domain core

`crates/dokkomplekt-core/src/source_parser.rs` извлекает факты по меткам, таблицам, типам и обученным правилам. `semantic_engine.rs` формирует типизированные предложения и evidence. Это первый и наиболее доверенный слой.

`semantic_llm.rs` не является транспортом к модели. Он валидирует и объединяет предложения SemanticModel: проверяет evidence, типы, контрольные суммы, конфликты и confidence.

## 3. Транспорт локальной модели — Tauri shell

`src-tauri/src/semantic_model.rs` реализует только loopback-транспорт к Ollama или OpenAI-compatible llama.cpp. Он не содержит бизнес-правил и не имеет права напрямую писать итоговый документ.

Полный офлайн-релиз обязан включать проверенные SHA-256 runtime и GGUF либо явно отключать модель. Source-архив не притворяется, что сторонние веса уже поставлены.

## 4. Workflow — один канонический контракт

`crates/dokkomplekt-core/src/core/workflow_contract.rs` — единственный низкоуровневый контракт построения workflow. `workflow_engine.rs` и `workflow_scenario_engine.rs` верхнего уровня используют его для разных представлений, но не должны содержать независимые правила обязательности.

## 5. Генерация и гранулярный resume

`document_generation.rs` оркестрирует комплект и атомарную публикацию. `dokkomplekt-docx` владеет WordprocessingML-рендером. Tauri-команды только преобразуют DTO, вызывают ядро, журналируют результат и управляют ОС-интеграцией.

`src-tauri/src/resume_engine.rs` не является вторым генератором. Он вычисляет content-addressed fingerprint одного документа и управляет checkpoint-копиями. Fingerprint включает только те semantic values, collections и named blocks, которые реально использует конкретный шаблон, плюс байты шаблона, версию приложения и watermark. Поэтому изменение постороннего поля не инвалидирует весь комплект. Счётчики, изображения и расчёты рабочих дней считаются зависимостями от внешнего состояния и всегда перерисовываются: подписанный календарь может обновиться независимо от версии приложения.

`dokkomplekt-storage` хранит `case_run_documents`. Checkpoint фиксируется сразу после успешного рендера документа, а после атомарной публикации запись переводится на итоговый путь. Повтор дела переиспользует только совпавшие fingerprint и существующий проверенный файл.

## 6. Zero-touch и risk-gate

Цель конвейера — **ноль молчаливых ошибок**, а не искусственные 100% бесшумных запусков. Значения высокого риска проходят автоматически только при достаточной уверенности, валидном evidence и доменных инвариантах. Иначе создаётся исключение для пакетного подтверждения.

Подтверждение пользователя:

1. повышает доверие только к конкретному значению;
2. может создать layout-scoped learned rule;
3. не отключает content-hash дедуп, processing lease или аудит;
4. не превращает свободный текст в глобальное правило без fingerprint.

## 7. Эксплуатация

`workspace_hygiene.rs` владеет `_обработано`, retention, legacy marker migration и служебными заметками. `main.rs` не должен реализовывать параллельную политику удаления файлов.

Processing lock — атомарная lock-directory с host-scoped lease и heartbeat. По умолчанию это полностью локальная файловая SHA-256 очередь. Для настоящего многомашинного режима `central_queue.rs` обращается только к отдельному HTTPS/mTLS queue service: source SHA-256 захватывается транзакционно, lease привязывается к worker и клиентскому сертификату, продлевается по этапам и завершается receipt. Недоступная явно сконфигурированная очередь блокирует распределённую обработку fail-closed.

Desktop не содержит PostgreSQL credentials и не открывает прямое соединение с БД. Queue service использует SQLite для одного узла либо PostgreSQL с `sslmode=verify-full|verify-ca` за серверной границей. Без mTLS-настройки сеть вообще не требуется.

Tauri shell физически разделён на четыре subsystem-файла (`update_runtime`, `desktop_io`, `document_commands`, `automation_runtime`). Они подключаются в одной crate-области и не имеют права дублировать parser/workflow/renderer из core.

## 8. Что не является готовой функцией

- юридически значимая КЭП через КриптоПро/Госключ;
- подтверждённый PDF/A-1A без veraPDF;
- гарантированное понимание буквально любого документа;
- кроссплатформенная Word-вставка изображений без реального LibreOffice UNO E2E;
- production-инсталлятор без полного Rust-gate, подписанных sidecar и Windows E2E.
