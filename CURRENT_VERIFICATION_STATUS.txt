Dokkomplekt Universal 18.4.3 — CURRENT VERIFICATION POLICY
Updated: 2026-08-04

This file deliberately does not duplicate volatile test counts. Exact counts, logs, commit SHA and artifacts are recorded by GitHub Actions for the same commit; a historical number in a source file is not release evidence.

Mandatory checks for every current pull request / release candidate:
- Rust 1.97.1: fmt, locked workspace check, clippy -D warnings and tests for all targets.
- RustSec: locked dependency audit with warnings denied.
- Frontend: TypeScript typecheck, Vitest runtime-validation/UI tests, production Vite build and npm audit.
- Python regression contour: isolated sharded contracts with machine-readable JSON evidence, source-quality gate, starter-pack and reference-data checks.
- PostgreSQL: a real PostgreSQL 16 service, mandatory DATABASE_URL, multi-connection concurrency tests, storage contract and HTTP integration flows. DOKKOMPLEKT_REQUIRE_POSTGRES_TESTS=1 makes a missing database fail instead of skip.
- Linux: AppImage/DEB/RPM build, install/launch smoke, React -> Tauri -> Rust IPC proof and native WebKitGTK X11 pixel-golden evidence.
- Windows: NSIS build/install/launch/uninstall smoke; signed production release remains separately gated by Authenticode and hardware E2E.
- macOS: native application and DMG build smoke, bundle metadata, signature-envelope and disk-image verification.
- Source provenance: deterministic clean source archive, manifest, Cargo metadata and Git history bundle bound to the same commit.

Current corrective scope:
- fail-closed license-server configuration, authenticated payment retry, verified-provider-only production billing and idempotent webhook storage;
- strict legal/financial validators, bounded rate-limit state, separated development CSP and hardened Windows signing trust boundary;
- one final selected-document plan is used for both preflight and generation popup;
- profession profiles cannot force runtime questions absent from selected templates;
- learned scanner rules, learned-kit decisions and template approvals are manageable in the UI;
- technical field identifiers are not shown in the normal popup;
- oversized App and universal-intake modules are decomposed into focused support, archive and web modules.

Production boundary:
- this source tree is not, by itself, a signed production release;
- production-sidecar binaries/model weights are not asserted present unless a signed component catalog and release artifacts prove them;
- licensed Word, real printer/spooler, watcher-after-reboot and signed EXE/NSIS evidence require the dedicated Windows hardware workflow;
- measured domain accuracy requires a representative anonymized professional corpus and approved templates.
