# Dokkomplekt Universal 18.1.2 — grounding, distributed intake and release hardening

## Исправленные подтверждённые дефекты

1. Закрыт реальный compile blocker: `apply_model_output_with_source` теперь экспортируется из `dokkomplekt-core` и доступен Tauri-shell.
2. Устранена бесконечная рекурсия `pdf_print_settings`, которая могла завершить процесс stack overflow при подготовке PDF-печати.
3. Watcher больше не принимает первое чтение за подтверждение стабильности. Источник допускается к intake только после отдельного повторного чтения с теми же размером, mtime и SHA-256.
4. Межкомпьютерная дедупликация для общей папки переведена на content-addressed очередь `.dokkomplekt-queue`: claim и completion receipt адресуются SHA-256 источника, создаются атомарно и поддерживают heartbeat/stale recovery.
5. LLM-grounding больше не ограничивается проверкой наличия цитаты. Пробелы, переносы, NBSP, кавычки и тире нормализуются; значение обязано быть локализуемым внутри evidence. Реальная цитата с чужим значением отклоняется.
6. High-risk модельные поля требуют минимум двух независимо полученных одинаковых grounded-ответов. Однопроходный режим для auto zero-touch запрещён.
7. Добавлен явный shadow-mode: модель применяется только к клону semantic case, а в audit/ROI попадают агрегированные предложения, совпадения и grounding-отклонения без чувствительных значений.
8. Подписанный календарный JSON можно импортировать из UI как ограниченный byte payload; arbitrary filesystem path пользователю не требуется.
9. Production Rust paths получили отдельный source-аудит на прямые `unwrap()/expect()/panic!/todo!/unimplemented!`; тестовые модули не смешиваются с production-результатом.
10. Вставка `{{image ...}}` перенесена из Word COM в прямой OOXML-путь. Тело, колонтитулы, сноски и комментарии используют один кроссплатформенный механизм с relationships, content types, лимитом изображения и атомарной заменой DOCX.
11. Добавлен реальный DOCX fixture с таблицами, колонтитулами, сносками, комментариями и media; Rust golden-test проверяет рендер и сохранение частей архива.
12. Добавлена консервативная локальная авто-классификация medical/legal/HR/education/accounting. Один слабый признак не переключает профиль.

## Календарь

Встроенный справочник остаётся fail-closed. Дополнительно реализован подписанный Ed25519 runtime-feed: HTTPS-only, DNS pinning, запрет proxy/redirect, лимит размера, SHA-256 содержимого, атомарный cache и повторная проверка при запуске. Неподтверждённый год не превращается в молчаливый weekend-only расчёт.

## Подписанный офлайн-runtime и Windows-релиз

- Runtime ZIP строится детерминированно только из предварительно SHA-256-проверенных sidecar/model файлов и содержит SBOM.
- Detached Ed25519-подпись проверяется относительно заранее закреплённого public key. Public key, приложенный к самому artifact, не является корнем доверия.
- Windows pipeline сначала собирает application EXE без bundle, подписывает и проверяет его, затем создаёт NSIS и подписывает установщик.
- Отдельный self-hosted hardware workflow требует Word, выделенный принтер, параметры duplex/tray, подписанный installer, установку, повторный запуск и autostart watcher evidence.

## Честные ограничения

- В текущей среде отсутствует Rust 1.85.1/cargo, поэтому новый Rust-код здесь не компилировался. Архив не содержит `.cargo-gate` и не называется `RUST_GATE_PASSED`.
- Hardware/Windows workflow создан, но не выполнен в этой среде. Для production нужен его зелёный artifact.
- Source ZIP не содержит лицензированные Tesseract/Poppler/LibreOffice/SumatraPDF/llama.cpp/GGUF. Он содержит fail-closed staging/signing pipeline; реальный offline runtime формируется на защищённом release runner.
- Shared-folder queue снижает риск двойной обработки на обычных SMB/NFS, но не является распределённым consensus-сервисом. Для недоверенных/нестандартных сетевых FS и нескольких площадок нужен отдельный central queue service.
- PDF/A остаётся кандидатом до независимой veraPDF-проверки. Hand-off КЭДО не заменяет КриптоПро/Госключ и не доказывает соответствие 152-ФЗ.
- «Любой документ» означает безопасный расширяемый intake. Новый layout может потребовать короткого подтверждения; целевой инвариант — ноль молчаливых ошибок, а не выдуманная 100% автономность.
