# Dokkomplekt Universal 18.4.4

Локальный офлайн-конструктор комплектов DOCX/DOCM на **Tauri 2 + React + TypeScript + Rust + SQLite**. Проект предназначен для расширяемой автоматизации процессов специалистов и работает с их собственными шаблонами. «Универсальный» здесь означает единое ядро для подключаемых форматов и доменных профилей, а не обещание безошибочно понять буквально любой неизвестный документ.

## Статус 18.4.4

Это **исправленный source-checkpoint 18.4.4**, а не подписанный production-релиз. На текущем дереве подтверждены полный Python/pytest-контур, source-quality gate, starter/reference-data проверки и детерминированная целостность исходного архива. Изменённые Rust-модули, frontend, RustSec, offline runtime и Windows hardware E2E обязаны быть повторно проверены на штатных CI/Windows runners перед релизом; исторические отчёты это не заменяют.

Production-релиз по-прежнему допускается только после актуального RustSec-аудита с доступной advisory database, защищённой CI-attestation и self-hosted Windows hardware E2E с реальными Word, watcher-after-reboot, принтером, подписанными EXE и NSIS. Исходный архив не содержит production-sidecar binaries или утверждённые модельные веса.

## Что входит в 18.4.4

### Corrective semantic-schema closure

The current source tree also includes a corrective closure pass: historical field ids are migrated into one canonical state, zero-touch risk checks are alias-aware, owner/provider and counterparty roles are separated, and starter-pack manifests are verified against the placeholders physically present in each DOCX. The incomplete EXE build shortcut was removed. Details and the exact verification boundary are recorded in `V18_2_2_SEMANTIC_SCHEMA_CLOSURE_REPORT.md`.

### Adversarial correctness hardening

- LLM consensus uses distinct sampling profiles instead of repeating one deterministic answer;
- name/address grounding rejects a different patronymic, house or apartment even when part of the citation matches;
- watcher classifies transient/permanent failures, retries only bounded transient cases and hashes event-pending paths instead of the full folder every two seconds;
- processing identity includes source, templates, workflow, calendar, engine and semantic runtime;
- resumed documents are reused only after SHA-256 and size verification;
- queue claims receive background heartbeat and completed/retryable records have retention;
- downloaded llama.cpp/GGUF is started and health-checked by a managed runtime supervisor;
- interrupted component upgrades recover only a fully hash-verified previous version;
- runtime JSON state is encrypted and new audit-chain entries are HMAC-keyed;
- the old forgeable text Cargo marker is replaced by an Ed25519-signed attestation bound to source, Cargo.lock, commit and CI run;
- Windows release evidence requires an exact installed Dokkomplekt EXE, Authenticode, spooler completion and two different OS boot identifiers;
- the DOCX corpus now contains seven structural and visual golden fixtures.

### Гранулярное восстановление комплекта

- после каждого успешно созданного документа сохраняется отдельный зашифрованный checkpoint и запись `case_run_documents`;
- повтор прерванного дела не обязан заново создавать уже доказанно неизменившиеся документы;
- fingerprint v2 учитывает точные байты шаблона, версию приложения, watermark и только реально используемые этим документом поля, коллекции и именованные блоки;
- изменение постороннего поля больше не инвалидирует весь комплект;
- блоки обходятся рекурсивно, а алиасы полей сводятся к каноническим кандидатам;
- шаблоны со счётчиками и изображениями консервативно создаются заново, потому что зависят от изменяемого внешнего состояния;
- UI показывает, сколько документов переиспользовано и сколько создано заново.

### Центральная очередь для нескольких компьютеров

- добавлена опциональная центральная SHA-256 очередь через отдельный HTTPS/mTLS service; desktop не получает PostgreSQL credentials;
- захват выполняется транзакционно через `SELECT ... FOR UPDATE`, worker identity и renewable lease;
- завершённый source hash получает completion receipt, аварийно прерванный worker переводит задание в `retryable`;
- если центральная mTLS-очередь явно настроена, но недоступна, распределённая обработка блокируется fail-closed и не откатывается незаметно к локальному lock;
- без mTLS-настройки продолжает работать полностью автономная файловая SHA-256 очередь для одного компьютера или ограниченного shared-folder сценария;
- PostgreSQL допускается только как backend отдельного queue service и требует проверяемый TLS; прямого database transport в desktop нет.

### Декомпозиция Tauri runtime

- `main.rs` сокращён примерно с 8,5 тыс. до 2,2 тыс. строк;
- runtime механически разделён на `update_runtime`, `desktop_io`, `document_commands` и `automation_runtime`;
- все части остаются в одной crate-области и используют прежнее ядро — параллельные workflow/parser/renderer не созданы;
- регрессионный контракт запрещает снова разрастить `main.rs` или любой subsystem выше 3 000 строк.

### Автоматическое обслуживание календаря

- подписанный производственный календарь проверяется при запуске автоматически, но не чаще одного раза в 24 часа;
- состояние последней попытки записывается атомарно;
- сетевой, криптографический или содержательный сбой не заменяет последний валидный календарь;
- это автоматизирует доставку обновлений, но не отменяет необходимость своевременно публиковать подписанные официальные данные следующего года.

- пакетная загрузка пользовательских DOCX/DOCM и создание кнопок документов;
- детерминированное извлечение значений из текста и выбранного Word-файла;
- безопасный мастер разметки: автоматические кандидаты и выделение мышью в загруженном DOCX/DOCM заменяются на плейсхолдеры только после подтверждения;
- единый объединённый popup перед одиночной или пакетной генерацией: общие поля спрашиваются один раз на весь комплект, неверное обязательное значение не закрывает окно;
- конструктор popup-вопросов для каждого пользовательского документа: специалист задаёт текст, смысловое поле, тип ответа, обязательность, режим «если не найдено / проверить / каждый раз», подсказку, варианты и связанное поле;

{{org.director_name | person_genitive}}
{{/if}}

Незакрытая конструкция, некорректная формула, неподтверждённый год производственного календаря, отсутствующее обязательное значение или неизвестный плейсхолдер в строгом режиме блокируют создание документа. Исходный текст выражения никогда не попадает в результат как fallback.

## Семантический слой без ложных обещаний

Детерминированный парсер меток, дат, реквизитов, таблиц и обученных scanner-правил остаётся первым и самым доверенным уровнем. Начиная с 18.1.0 встроен **транспорт** к локальному Ollama или OpenAI-compatible llama.cpp server на `localhost`/loopback. Source-архив не содержит runtime и веса модели. Полный офлайн installer 18.4.4 может быть собран только после SHA-256-проверенного staging llama.cpp и GGUF через sidecar manifest; без них release-сценарий блокируется. Внешние адреса, proxy и redirects для этого транспорта запрещены.

SemanticModel не получает право напрямую писать итоговый документ. Он возвращает предложения полей, confidence и по возможности дословную evidence-цитату. Rust нормализует пробелы/переносы/кавычки, проверяет присутствие цитаты и локализуемость proposed value внутри неё, затем применяет типовые и контрольные валидаторы. High-risk поля требуют минимум двух согласованных grounded-проходов. Поддельное доказательство отбрасывается, а значение без доказательства понижается по доверию и не должно проходить high-risk zero-touch молча.

Неразмеченный DOCX не становится динамическим шаблоном автоматически. Мастер показывает кандидатов и изменяет отдельную копию документа только после подтверждения пользователя. Подтверждённые scanner-правила сохраняются локально и повторно используются для похожих документов, но область их безопасного обобщения всё ещё требует реального доменного корпуса и shadow-mode наблюдения.

## Уточняющие popup-окна и уникальность комплектов

Перед созданием одного документа или всего выбранного комплекта Workflow Engine строит одно окно из требований шаблонов, отраслевого профиля и вопросов, созданных самим специалистом. Одинаковое смысловое поле, например `document.date`, `subject.name` или `org.inn`, спрашивается один раз и затем используется во всех документах комплекта.

Для каждого вопроса доступны режимы:

- **только если не найдено** — не мешает автоматическому распознаванию;
- **показать найденное для проверки** — специалист подтверждает или исправляет значение;
- **спрашивать каждый раз** — подходит для номера и даты договора, приказа, счёта, протокола и других реквизитов, меняющихся в каждом комплекте.

Вопросы создаются вручную или из выделения мышью. Связанные даты могут первоначально повторять основную дату, но остаются независимо редактируемыми. Подтверждённый ответ получает приоритет `UserConfirmed` и не перезаписывается scanner-значением. Загрузка нового источника начинает чистый case; настройки шаблонов, вопросы и библиотека блоков при этом сохраняются.

## Сканер мышью для неподготовленного пользователя

Основной сценарий не требует знания плейсхолдеров или идентификаторов полей:

1. Выберите исходный DOCX/DOCM или пользовательский шаблон.
2. Нажмите «Открыть Word и показать значение мышкой».
3. В Word выделите значение; для одного слова или номера достаточно поставить курсор внутрь.
4. Вернитесь в Доккомплект и нажмите «Я показал значение».
5. Программа предложит понятный вариант («Номер договора», «ИНН», «ФИО», «Дата выписки» и т. п.), покажет документы, где поле уже используется, и после подтверждения сама закроет Word.

Если выбран не тот фрагмент, кнопка «Выделить другое» возвращает Word на передний план без потери сеанса. Короткие служебные слова вроде «от» и «до» распознаются только как отдельные токены: «работник» и «договором» больше не превращают адрес или ФИО в дату. Когда два варианта близки по уверенности, программа честно просит выбрать, а не подставляет первый. Если Word оказался за другими окнами, доступна кнопка «Word не видно? Открыть документ ещё раз». Технические имена полей и ручной режим скрыты и нужны только опытному пользователю.

При разметке шаблона исходный файл никогда не перезаписывается: создаётся безопасная копия. Перед заменой backend повторно сверяет путь, координаты и текст выделения; если пользователь успел изменить выделение, разметка блокируется без частичного изменения документа.

## Единый финальный план и управление обучением

- предварительная проверка и popup генерации строятся одним и тем же single/batch workflow-plan для фактически выбранных документов;
- обязательность ограничена физическими плейсхолдерами выбранных шаблонов и явно сохранёнными специалистом вопросами; отраслевой профиль предлагает поля в конструкторе, но не навязывает их runtime;
- технические идентификаторы полей скрыты из пользовательского popup;
- в настройках доступны удаление обученных scanner-rule, просмотр learned-kit decision, список подтверждений шаблонов и отзыв подтверждения;
- PostgreSQL storage/concurrency/HTTP тесты запускаются в обязательном CI job с настоящим PostgreSQL и не могут молча пропуститься;
- добавлены macOS app/DMG smoke и нативная Linux WebKitGTK pixel-golden проверка.

## Конфиденциальность

- основное ядро работает офлайн;
- сетевые интеграции по умолчанию отсутствуют или выключены;
- semantic case сохраняется в зашифрованном виде;
- стандартное имя выходной папки обезличено;
- ФИО в имени папки включается только явной настройкой;
- DOCX/DOCM и временные staging-файлы обрабатываются локально.

Наличие технического шифрования само по себе не является автоматическим подтверждением соответствия 152-ФЗ: для этого дополнительно требуются модель угроз, организационные меры, разграничение доступа, журналирование и регламент эксплуатации.

## Adversarial hardening, сохранённый в 18.4.4

После разрушительного аудита исправлены классы риска, которые могли дать неверный reuse или вечную остановку: plan-bound dedup, SHA-256 каждого checkpoint-результата, retry transient watcher failures, distinct LLM consensus sampling, более строгий grounding ФИО/адресов, component transaction recovery и supervised downloaded llama.cpp runtime. Cargo release evidence теперь является Ed25519-подписанной аттестацией, а Windows evidence требует spooler completion и доказательство двух разных загрузок ОС. Подробности: `V18_2_2_ADVERSARIAL_HARDENING_REPORT.md`.

## Исторический baseline 18.0.8

Версия 18.0.8 закрыла молчаливые ошибки zero-touch: единое имя attention-файла, корректную проверку плейсхолдеров прежнего поколения, безопасную печать Office-документов через PDF вне Windows, неоднозначности порядка ФИО и DNS-rebinding в подписанном обновлении. Её доказательства относятся только к дереву 18.0.8 и не подтверждают изменённый Rust-код 18.2.2.

## Что не объявляется готовым в 18.4.4

- фактические model weights и готовая поставка Ollama/llama.cpp runtime; встроен безопасный loopback-транспорт, а не сама модель;
- вложенные лицензированные бинарники Tesseract/Poppler/LibreOffice/7-Zip/msgconvert: есть hash-verified staging и Tauri resource wiring, но в source-кандидате они не поставляются;
- сертифицированный PDF/A-1A: создаётся PDF/A-кандидат, обязательна независимая veraPDF/профильная проверка;
- юридически значимая ЭП через КриптоПро/Госключ: создан hand-off пакет и слоты `.sgn`, подпись не подделывается;
- реальные одобренные Tier-1 отраслевые тексты: поставляются только workflow-каркасы со строгим запретом статуса `pilot/approved` без проверенных DOCX/DOCM;
- ЕГРЮЛ/ЕГРИП, СЭМД/ЕГИСЗ и иные внешние интеграции;
- подтверждённая работа image placeholders во всех Word story ranges, драйверах принтеров, лотках и дуплексе; необходим Windows E2E;
- Windows NSIS/Word/watcher/reboot/print E2E текущего дерева;
- актуальный Rust gate, PostgreSQL integration gate и платформенные installer-smoke проверки текущего commit;

Полная граница доказанности зафиксирована в `RELEASE_VERIFICATION_V18_2_2.md`.

## Межкомпьютерная очередь

По умолчанию watcher использует автономную content-addressed файловую очередь и не обращается к сети. Для нескольких компьютеров можно явно настроить `DOKKOMPLEKT_QUEUE_MTLS_URL`, CA и клиентский PEM: desktop обращается к узкому HTTPS/mTLS queue service, lease привязан к SHA-256, worker и сертификату. PostgreSQL при необходимости находится только за сервисом и подключается с проверяемым TLS. Инструкция: `docs/QUEUE_SERVICE_DEPLOYMENT.md`.

## Производственный календарь

Встроенные данные 2025 и 2026 помечены как полные. 2027 присутствует как `provisional`. Приложение автоматически проверяет подписанный feed не чаще одного раза в 24 часа; до получения полного подписанного года расчёт `working_days` для него намеренно завершается ошибкой до добавления подтверждённых переносов. Выход за диапазон подтверждённых лет также блокируется — weekend-only fallback отсутствует.

## Печать

Для каждой пользовательской кнопки задаётся собственное количество экземпляров `0..99`; `0` означает «создать, но не печатать». Настройки сохраняются локально и применяются к ручной печати, автопечати и фоновому watcher. После одиночной, пакетной или zero-touch генерации интерфейс показывает готовый результат и позволяет ещё раз изменить количество экземпляров по каждому файлу. На Windows Word-документы печатаются одним COM-вызовом `PrintOut` с нужным числом копий, а не N отдельными запусками обработчика. PDF на Windows печатается через проверенный SumatraPDF-sidecar, а на Linux/macOS — через CUPS `lp`; printer/copies/duplex/tray передаются явно; в печать попадают только созданные документы, не исходник и не отчёт доверия.

## Сборка и проверка

Исходный архив предназначен для репозитория и сборочного сервера. Конечному пользователю Windows нужен отдельно собранный и проверенный NSIS `setup.exe`.

```bash
npm ci
npm run typecheck
npm run test
npm run build
npm run test:python

cargo fmt --all -- --check
cargo check --workspace --all-targets --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

Полный fail-closed gate:

```bash
bash scripts/prepackage_rust_gate.sh
python scripts/assert_release_ready.py
```

После реального Rust-прогона создаются Ed25519-подписанные `.cargo-gate/CARGO_GATE_ATTESTATION.json` и `.sig`, связанные с fingerprint исходников, `Cargo.lock`, commit SHA и CI run. Обычный текстовый marker не считается доказательством.
