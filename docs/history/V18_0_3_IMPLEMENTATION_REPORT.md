# Dokkomplekt Universal 18.0.3 — отчёт реализации

## 1. Независимое количество копий

Для каждой пользовательской кнопки документа добавлено отдельное число экземпляров печати `0..99`. Значение `0` означает «создать документ, но не печатать». Настройки сохраняются только локально и применяются к:

- ручной печати готового комплекта;
- автопечати после одиночной и пакетной генерации;
- zero-touch обработке папки «Созданные документы»;
- фоновому watcher после перезапуска приложения.

Backend принимает типизированные задания `path + copies`, считает реально отправленные экземпляры и сообщает частичный успех отдельно от ошибки. Связь результата с кнопкой сохраняется через `document_id`, поэтому переименование файла или кнопки не смешивает настройки копий.

## 2. Визуальный сканер курсором

Перенесён полезный принцип из старого Dokkomplekt, но без медицинской привязки:

- пользователь выделяет мышкой фрагмент текста источника;
- назначает универсальное смысловое поле;
- значение поступает в `ScannerMark` с приоритетом ниже подтверждённого пользователем popup/UI;
- уже исправленное пользователем значение сканер не перезаписывает.

Сканер работает и с вручную вставленным текстом, и с загруженным DOCX/DOCM: специалист выбирает шаблон, выделяет примерное значение мышью и назначает смысловое поле. Доступны два действия: заменить выделенный пример на `{{field.id}}` либо вставить плейсхолдер после выделения. Для Word-файла создаётся отдельная размеченная копия; исходный файл, форматирование, таблицы и DOCM-макросы не перезаписываются. DOCX-слой использует те же действия `replace` и `insert_after`.

## 3. Медицинский профиль-донор

Из `mailsvb2-bot/Dokkomplekt` и `mailsvb2-bot/diary-filler` перенесены только профильные контракты, которых не хватало:

- номер протокола;
- номер комиссии;
- номер акта/заключения РВК;
- дата начала больничного;
- состояние при выписке;
- роли «ВК больничный» и «Осмотр врача приёмного покоя»;
- сохранён приоритет UI/popup над scanner;
- сохранены отдельные источники дат и текстов серийных/дневниковых записей.

Встроенные медицинские шаблоны, готовые клинические тексты и медицинские сущности в универсальное ядро не добавлялись. Все новые правила находятся в медицинском профиле и его реестре полей.

## 4. Проверки в текущей среде

Пройдены TypeScript typecheck, 14/14 Vitest, production frontend build и Python regression tests. Rust toolchain в среде отсутствует, поэтому Cargo/Clippy не объявляются пройденными; коммерческий release gate остаётся fail-closed до запуска `scripts/prepackage_rust_gate.sh` на машине с Rust 1.85+.
