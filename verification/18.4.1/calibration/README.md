# Артефакты калибровки 18.4.1

Воспроизводимо из поставки:

```bash
# 1. Сгенерировать корпус (1000 записей на профессию, 5000 всего)
cargo run -p dokkomplekt-core --example corpus_simulation 1000 > corpus.json

# 2. Откалибровать порог по каждому домену с holdout 20% и целью 1% ошибки
for d in accounting hr legal medical education; do
  python3 scripts/calibrate_thresholds.py corpus.json --domain "$d" \
    --output "verification/18.4.1/calibration/$d.json" \
    --target-auto-error-rate 0.01
done
```

## Результат (цель ошибки автопечати 1%, корпус 5000 записей)

| домен | auto_min_confidence | holdout ошибок | статус |
|---|---:|---:|---|
| accounting | 0.8683 | 4 / 786 (0.51%) | откалибровано |
| hr | 0.8830 | 2 / 421 (0.48%) | откалибровано |
| legal | 0.8582 | 2 / 335 (0.60%) | откалибровано |
| medical | 0.9014 | 2 / 398 (0.50%) | откалибровано |
| education | — | — | **fail-closed** |

education честно отказался: на этом корпусе он не удержал 1% на holdout.
Это правильное поведение — калибратор не подгоняет порог, а запрещает
автопечать там, где данных не хватает.

## Важное свойство: чувствительность к цели и размеру

При цели 0.5% (вместо 1%) картина другая — калибруется меньше доменов,
и какие именно — зависит от того, какие записи попали в holdout по хешу
`entry_id`. Это НЕ недетерминизм калибратора (при фиксированном корпусе
результат детерминирован), а его консервативность у пограничных доменов,
чья истинная ошибка близка к целевой.

## Оговорка

Корпус — синтетическая МОДЕЛЬ. Пороги здесь доказывают, что цепочка
работает, но НЕ являются производственными: их нельзя переносить на
реальные документы. Производственная калибровка требует настоящего
корпуса, набранного `corpus_recorder` в эксплуатации.
